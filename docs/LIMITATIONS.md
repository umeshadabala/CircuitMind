# CircuitMind — Engineering Limitations and Verification Disclosures

In accordance with core engineering principles, CircuitMind maintains complete transparency regarding simulated vs. physical verification.

## 1. Simulation vs. Physical Reality
- **Behavioral Simulation**: CircuitMind's built-in simulation layer verifies logical state transitions, threshold triggers, state-machine invariants, and pin mapping contracts. It models logical time and component state machines.
- **SPICE / Transient Physics**: The behavioral simulator does NOT perform continuous-time SPICE solving, electromagnetic interference (EMI) modeling, thermal dissipation analysis, or trace impedance simulation.
- **Physical Hardware Tests**: No physical hardware was connected or physically tested unless explicit bench instrumentation is reported. Designs generated by CircuitMind must be reviewed by an engineer before applying live power.

## 2. Electrical Validation (DRC)
- CircuitMind's Design Rule Checker checks explicit rules:
  - Voltage level compatibility (e.g. 5V logic to 3.3V GPIO inputs).
  - Pin direction conflicts (e.g. two output pins driving the same net).
  - Missing power/ground rails on active components.
  - Strapping pin conflicts on ESP32 (GPIO0, GPIO2, GPIO12, GPIO15).
  - Input-only pin restrictions (ESP32 GPIO34-GPIO39 cannot be outputs).
  - Current-limiting resistor presence in series with LEDs.
  - Pull-up resistor presence on open-drain or active-low lines.
- Passing DRC does NOT guarantee complete analog stability or immunity from ground loops or high-frequency noise.

## 3. Firmware Compilation
- Firmware is emitted as standards-compliant C++/Arduino code targeting the ESP32 framework.
- If the target compiler (`esptool`, `arduino-cli`, or `xtensa-esp32-elf-g++`) is not installed on the host machine, the firmware is marked as **Generated (Uncompiled)** rather than claiming a successful build.

## 4. AI Invocations
- All AI processing executes against local Ollama.
- If the local Ollama instance is unreachable, the system will not silently fallback to any cloud provider or fabricate an artificial response. It surfaces a clear diagnostic explaining that the local Ollama endpoint was unreachable.
